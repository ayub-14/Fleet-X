# Pre-Publication Security Audit — FLEET-X

**Date:** 2026-10-30
**Scope:** files intended for the public `ayub-14/FLEET-X` repository.
**Result:** no credentials or private keys found in the files selected for
publication.

This document intentionally does not reproduce any secret value. If a secret were
found, it would be excluded, rotated, and removed from history before publishing.

## 1. Method

The following checks were run across source, documentation, launch files,
configuration and scripts:

- high-entropy / known token patterns (GitHub tokens, cloud access keys),
- private-key headers,
- password, API-key, secret and token assignments,
- personal email addresses and absolute home-directory paths,
- nested Git repositories and third-party code,
- build artefacts, logs, recordings and simulation output,
- file sizes and generated binaries.

## 2. Findings

| Category | Result |
|---|---|
| GitHub / cloud tokens | None found |
| SSH / TLS / GPG private keys | None found |
| Passwords or API keys | None found |
| Wi-Fi credentials | None found |
| Personal email addresses in tracked source | None; package maintainer uses the project placeholder `fleetx@example.com` |
| Absolute personal paths in tracked files | None; docs use `~/fleet_x_ws` or repository-relative paths |
| Large generated files | Excluded via `.gitignore` (`build/`, `install/`, `log/`, bags, recordings) |
| Nested Git repository | `src/articubot_one/.git` exists locally and is excluded from publication |

## 3. Third-party and licence review

### Articubot One

`src/articubot_one` is a modified copy of
`https://github.com/joshnewans/articubot_one` at commit `da6b40b`. Its
`package.xml` declares `TODO: License declaration`, and the repository has no
`LICENSE` file. It therefore **cannot be redistributed** in this public
repository.

It is excluded by `.gitignore` and is not part of the FLEET-X build
(`COLCON_IGNORE`). The custom FLEET-X package does not depend on it.

### `fleet_ros2_control_plugins`

This local package was an abandoned workaround that re-registered the
`gz_ros2_control` hardware plugin and attempted to symlink into `/opt/ros`. It
is excluded from the build via `COLCON_IGNORE`, is not needed on ROS 2 Jazzy, and
is excluded from publication as dead code.

### Dependencies

ROS 2, Gazebo, `ros2_control`, `diff_drive_controller`, `slam_toolbox` and
`ros_gz_*` are used as external dependencies under their own upstream licences.
They are not copied into this repository and are not claimed as FLEET-X code.

## 4. Files deliberately excluded

- `build/`, `install/`, `log/` — generated by colcon and Gazebo.
- `src/articubot_one/` — unlicensed third-party code.
- `src/fleet_ros2_control_plugins/` — abandoned compatibility shim.
- `DEMO_GUIDE.md`, `DEMO_READINESS_PASS_FAIL.txt`,
  `ARTICUBOT_PROGRESS_LOG.txt`, `demo_screenshot.png` — legacy single-robot
  Articubot demo material that does not describe the current FLEET-X stack.
- `docs/*.txt` — duplicate plain-text versions of the Markdown reports.
- `base_link`, `laser` — empty files left by an earlier experiment.
- `scripts/phase2*.sh` — ad-hoc development checks superseded by
  `tests/smoke_test.sh`.

These files remain on the local workstation; they are only excluded from the
public repository.

## 5. Repository history

The workspace root `~/fleet_x_ws` was **not** a Git repository before this
publication. The only Git metadata inside it belongs to the excluded
`src/articubot_one` clone. Consequently there is no pre-existing FLEET-X history
that could contain a leaked credential.

After `git init`, the first commit contains only the audited files listed in the
publication report. If a secret is discovered later, removing it from the latest
commit is not sufficient: stop, rotate the credential, and rewrite the affected
history before pushing.

## 6. Residual risks

- The simulator environment is reproducible only on a compatible ROS 2
  Jazzy/Gazebo Harmonic installation.
- `demo_screenshot.png` (excluded) was captured from the older Articubot demo,
  not from FLEET-X. It is not used in the README.
- The public README uses repository-hosted screenshots captured from the
  current FLEET-X simulation; they contain no personal data.
- No automated secret scanner is configured in CI. Contributors must not commit
  credentials.

## 7. Recommendation

Publication is safe with respect to credentials and third-party licensing,
provided the exclusions in `.gitignore` remain in force and no secret is added
in later commits.
